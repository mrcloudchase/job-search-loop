# E1 parity slice: job-board skills (linkedin, freehire, jobbank) and /add-portal

SUMMARY
1. Files read in full: for each of linkedin-search, freehire-search, jobbank-search the SKILL.md, url-reference.md (linkedin, freehire, jobbank all have one), cli/README.md, every cli/src/**/*.ts and every cli/tests/*.ts plus linkedin's fixtures; also .claude/commands/add-portal.md and tests/test_add_portal_command.py. Paths in the tables are relative to the original checkout root; a bare cli/... path is under the skill named in the same cell.
2. 189 rows (mostly planned; ~10 marked not ported because they are human-facing table/plain views, framework help, or bun packaging).
3. The matrix cannot express: per-board live behaviour (Cloudflare walls, challenge pages, rate-limit headers) and selector drift; those live in the knowledge notes boards/linkedin.md, boards/freehire.md, boards/jobbank.md, and adapter fixtures are described there.
4. Surprising: (a) add-portal's only test is a string-presence check on one prose line, so every other add-portal guarantee (robots, auth wall, mandatory live test, personal-use banner) is prose-only with no test. (b) LinkedIn's robots.txt (checked live 2026-10-19) disallows everything for generic crawlers and names /jobs-guest/ explicitly, so the new robots gate will block the LinkedIn adapter; the original never checked robots. (c) jobbank was unreachable (Cloudflare 403 even for robots.txt) and its README claims a browser UA while the code sends an honest one; its --company flag is a numeric id in the CLI but a name in url-reference; its validation errors use a different JSON shape from every other error.
5. Contradictions pinned by tests: linkedin SKILL lists age values 1/7/14/30 but tests and code accept any whole number >= 1; the tests treat "-5" as an unknown flag (UNKNOWN_FLAG), not BAD_ARG, as a deliberate consequence of the flag parser.

Planned module names used: boards/contract (shared result shape, validation, error format), boards/http (fetch helper: UA, timeout, backoff), boards/linkedin, boards/freehire, boards/jobbank, guards.robots, search.filters (client-side filtering), addboard.
