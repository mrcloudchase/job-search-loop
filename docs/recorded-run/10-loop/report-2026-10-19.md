## Learning plan
### Azure foundations for a data engineer
- **Azure** (High, about 30 hours): Skip the generic 'what is the cloud' chapters on first pass: you already run Terraform and GitHub Actions and have moved a PostgreSQL warehouse to BigQuery, so concepts map quickly. Focus on resource groups, subscriptions, Entra ID/rbac, Storage (ADLS Gen2), Key Vault and Monitor, which are the pieces the other four gaps sit on. Start with the fundamentals path, do the guided projects, then take the practice assessment to decide whether to sit AZ-900.
  - [Microsoft Learn: Azure Fundamentals learning path](https://learn.microsoft.com/en-us/training/paths/azure-fundamentals/): Start here: gives the cloud-concepts, core-services and governance vocabulary on which Databricks, Data Factory and Snowflake-on-Azure all build.
  - [Microsoft Learn: Introduction to Cloud Infrastructure with guided Azure projects](https://learn.microsoft.com/en-us/training/paths/introduction-cloud-infrastructure-apply-azure-skills-guided-projects/): Hands-on counterpart to the fundamentals path so the subscription, storage and monitoring experience is not purely theoretical.
  - [Microsoft Certified: Azure Fundamentals (AZ-900) certification page](https://learn.microsoft.com/en-us/credentials/certifications/azure-fundamentals/): Use the skills outline and the free practice assessment to check coverage and to give recruiters a credential for Azure.
### Databricks platform and the lakehouse for data engineers
- **Databricks** (Critical, about 45 hours): Highest priority: five jobs name it. Skip the data-science and Feature Store tutorials and any Spark fundamentals you will cover separately. Start by signing up for Free Edition, then do the ETL/Lakeflow and SQL tutorials, mapping Lakeflow and Delta Live-style pipelines onto the Airflow + dbt orchestration you run today. Then take the Databricks Academy data-engineer learning plan; practise Unity Catalog, Delta tables, and reading/writing with PySpark in the workspace on your own shipment-events-shaped data.
  - [Get started with Databricks Free Edition](https://docs.databricks.com/aws/en/getting-started/free-edition): You need a workspace to practise in; the free edition removes the cost barrier and is the most practical first step.
  - [Databricks Learn (Databricks Academy)](https://www.databricks.com/learn): Official role-based learning plans pointed at data engineering; use the data-engineer path rather than browsing courses ad hoc.
  - [Get started tutorials on Databricks](https://docs.databricks.com/aws/en/getting-started/): Short guided tutorials (SQL, ETL with Lakeflow) to run in the free workspace; closest to the Airflow/dbt work you already do.
### PySpark for data engineers
- **PySpark** (High, about 40 hours): No reading has been fetched for this gap, so the plan below is study direction only; get sources before starting. Skip Python basics, SQL and distributed-systems theory you already have from 7 years of Python and Kafka pipelines. Start with DataFrame API, schema definition, joins and window functions in a notebook, then move to partitioning, shuffle behaviour, file layout and the Spark UI. Practise inside the Databricks Free Edition workspace so the PySpark time does double duty for the Databricks gap, and port part of your Airflow ingestion work onto it.

### Data integration and orchestration with Azure Data Factory
- **Azure Data Factory** (High, about 20 hours): Skip what you already own: orchestration and scheduling concepts, dependencies and alerting (45 cron jobs migrated to Airflow, delivery-delay alerting, the on-call runbook), SQL and transformations (7 years SQL, dbt models including incremental), PostgreSQL sources (your warehouse move to BigQuery), Python scripting (your REST/SFTP ingestion services) and Kafka (the shipment-events consumer), plus the SSIS section unless a target job asks for it. Start at the intro module only to learn the ADF object model (linked services, datasets, pipelines, triggers) and map it onto Airflow's operators, connections, DAGs and schedules, since both are the same concepts with different names. Then go hands-on: this gap is under 5 hours of new theory and about 15 hours of building and getting used to the portal UI. Use the quickstarts to build a parameterised pipeline that copies Parquet from ADLS Gen2 into the Databricks workspace created in the Databricks gap, add a tumbling-window trigger and a failed-activity alert, then rewrite part of your Airflow shipment-events or price-feed ingestion as an ADF pipeline.
  - [Introduction to Azure Data Factory (Microsoft Learn module)](https://learn.microsoft.com/en-us/training/modules/intro-to-azure-data-factory/): Microsoft's recommended first module; sets up the linked services, datasets, pipelines and triggers vocabulary before the longer path.
  - [Data integration at scale with Azure Data Factory (Microsoft Learn learning path)](https://learn.microsoft.com/en-us/training/paths/data-integration-scale-azure-data-factory/): Full official path covering mapping data flows, orchestration, SSIS (which you can skip) and operationalising pipelines.
  - [Summary of introductory training modules and quickstarts (Azure Data Factory docs)](https://learn.microsoft.com/en-us/azure/data-factory/quickstart-learn-modules): Index of quickstarts to build first pipelines in the portal; use for hands-on practice after the path.
### Snowflake for data engineers
- **Snowflake** (High, about 30 hours): No reading has been fetched for this gap, so the plan below is study direction only; get sources before starting. Skip SQL fundamentals, star-schema modelling and warehouse cost thinking — you designed a star schema and cut a BigQuery bill by 35 percent with partitioning and clustering. Start with Snowflake-specific architecture (virtual warehouses, storage separation), databases/schemas/roles and access control, then streams and tasks, Time Travel, cloning, Snowpipe ingestion, and finally Snowpark for Python. Use a free trial account and rebuild part of your delivery-performance mart with incremental models to compare against dbt on BigQuery.
