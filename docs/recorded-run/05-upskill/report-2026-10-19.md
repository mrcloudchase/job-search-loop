## Learning plan
### Data pipelines: frame seven years of production work as structured competence
- **Data pipelines** (High, about 6 hours): Skip the Airflow and dbt basics entirely: you run a 40M-events/day Kafka-to-BigQuery pipeline and hold a dbt certification. Spend the time instead turning the shipment-events pipeline into two or three rehearsed end-to-end stories (ingestion, transformation, quality, cost) and skimming the cookbook only for terminology you have not used in interviews. This is consolidation, not new learning.
  - [Apache Airflow tutorial (official docs)](https://airflow.apache.org/docs/apache-airflow/stable/tutorial/fundamentals.html): Your strongest area; use it to confirm current Airflow terminology (DAGs, task dependencies, scheduling) so you describe your work in the interviewer's vocabulary.
  - [dbt Fundamentals (dbt Learn)](https://learn.getdbt.com/courses/dbt-fundamentals): You already hold dbt certification; a skim refreshes the ELT framing (models, tests, deployment) for a coherent pipeline narrative.
  - [The Data Engineering Cookbook (Andreas Kretz)](https://cookbook.learndataengineering.com/docs/01-Introduction/): Broad map of pipeline components; skim it for gaps in vocabulary between your Airflow/dbt/Kafka experience and job-description language.
### CI/CD: from working knowledge to an explainable, designed practice
- **CI/CD** (High, about 8 hours): Do not start from the IBM Skills Network course basics; you have shipped real GitHub Actions deployments and Terraform environments. Focus on the concepts you have not had to explain: pipeline stages for data work, testing and promotion gates, environment promotion, secret handling, and how GitHub Actions and GitLab CI differ. Drop the IBM course unless interviews reveal a gap in the fundamentals.
  - [GitHub Actions documentation](https://docs.github.com/en/actions): You have already moved the team to GitHub Actions; this closes specific knowledge gaps (reusable workflows, environments, matrix builds, secrets) so you can design rather than copy workflows.
  - [GitLab CI/CD documentation](https://docs.gitlab.com/ci/): Many Copenhagen and remote data-platform teams use GitLab; learn the equivalent concepts (stages, pipelines, environments) to answer tool-comparison questions confidently.
### GitOps: declaring infrastructure state in Git and reconciling it continuously
- **GitOps** (High, about 10 hours): Build on your Terraform and GitHub Actions experience: you already run push-based infrastructure as code, so the new part is pull-based reconciliation, drift detection and Git as the single source of truth. Read the principles first, then work through Argo CD; only skim Flux if time allows. Do not spend time on Kubernetes administration itself (listed as not yet known) unless a target job requires it.
  - [OpenGitOps Principles (CNCF GitOps Working Group)](https://opengitops.dev/): Start here: the four principles give you a precise definition to contrast with your existing Terraform push-based deployments.
  - [Argo CD documentation – Getting Started](https://argo-cd.readthedocs.io/en/stable/getting_started/): Hands-on with the most common GitOps controller; enough to deploy a small app from a Git repo and understand sync and drift.
  - [Flux documentation – Get started guides](https://fluxcd.io/flux/get-started/): Use Flux to see a second controller implement the same principles; brief comparison notes are enough for interviews.
### DataOps: operating data pipelines like software
- **DataOps** (High, about 10 hours): Start with the manifesto, then take the DataKitchen certificate, because the tools it assumes are ones the profile lists as strong: Python for pipeline code and Great Expectations checks, SQL and PostgreSQL for the customer-orders star schema and query-level test assertions, Apache Airflow for retry/alert mechanics and for scheduling the monthly 45-job migration cohort, dbt for the tests and models this discipline runs on, and Kafka for the shipment-events stream. Skip tool tutorials for these; instead map each of the 18 principles to what the profile already shows (Great Expectations on 30 tables, the data contract with five producing teams, the 20-minute Terraform environment build, the on-call runbook, 15-minute Airflow alerting) and use the certificate to fill only the operational vocabulary. Use the Pluralsight course only if a concept stays unclear; avoid introductory material for CSV-and-spreadsheet teams.
  - [DataOps Manifesto (official site)](https://dataopsmanifesto.org/en/): Primary source: read the 18 principles first and map each one to something you already do or should do.
  - [DataKitchen – DataOps Fundamentals Certification](https://datakitchen.io/certifications/dataops-fundamentals/): Free, self-paced certificate that adds a verifiable credential in exactly this gap and walks through an implementation process.
  - [Pluralsight – DataOps Foundations: Core Concepts](https://www.pluralsight.com/courses/dataops-foundations-core-concepts): Use only if the manifest and certificate course leave conceptual gaps; optional and lower value for someone at your level.
### Data governance: frameworks, roles and enforcement in a cloud warehouse
- **Data governance** (High, about 14 hours): Skip general data-management chapters (storage, integration, modelling) where you are already strong. Focus on governance, data catalog and lineage, and how enforcement maps onto BigQuery IAM and your existing data contracts and partitioning work. Use Purview for the concrete picture and DMBOK for the vocabulary. Treat CDMP as a checklist, not a study target, unless a job asks for it.
  - [DAMA-DMBOK: Data Management Body of Knowledge (Revised 2.0 Edition)](https://dama.org/learning-resources/dama-data-management-body-of-knowledge-dmbok/): Authoritative framework; read the governance knowledge area for the vocabulary (stewards, owners, policies, maturity) interviewers expect.
  - [Microsoft Learn: Data governance with Microsoft Purview](https://learn.microsoft.com/en-us/purview/data-governance-plan): Concrete cloud implementation (catalog, domains, lineage); useful even if you stay on BigQuery, since the concepts transfer to Dataplex-like tools.
  - [CDMP Exams (Certified Data Management Professional)](https://cdmp.info/exams/): Optional: use the exam outline as a checklist of governance topics; only pursue the certification if a target role values it.

### Stakeholder management: from cross-team partner to tech-lead influence
- **Stakeholder management** (High, about 8 hours): Start with the PMI guide for the power/interest grid, then build a stakeholder map for your current pipelines using the technical relationships the profile describes: the five producing teams behind the shipment-events data contract and the Apache Airflow/Kafka ingestion and alerting dependencies, the two juniors you mentor and the weekly data-modelling review, the 12 analysts who use the dbt models and PostgreSQL star schema, the four teams on the warehouse migration guide, and the operations planners on the Looker explore. Python, SQL, PostgreSQL, Airflow, dbt and Kafka are only the content of those relationships; skip introductory definitions of stakeholders and skip tool learning. Rehearse two tech-lead stories: the data-contract negotiation and the move of four teams off the old warehouse. Treat Coursera as optional and GLOMACS as a last resort.
  - [Stakeholder Management — Free Study Guide (CAPM / PMI)](https://open-exam-prep.com/study-guides/capm/resource-communication-stakeholder-management/stakeholder-management): Free reference for the standard tools (registers, power/interest grids, salience and engagement matrices) that you can apply directly.
  - [Stakeholder Management (Coursera, CREO)](https://www.coursera.org/learn/stakeholder-management-creo): Short auditable course on influence and long-term engagement; optional, mainly for structure and practice exercises.
  - [Managing Project Stakeholders (GLOMACS)](https://glomacs.sa/training-course/managing-project-stakeholders): Instructor-led programme on conflict resolution and communication; use only if targeted practice with others is needed, not the default.
